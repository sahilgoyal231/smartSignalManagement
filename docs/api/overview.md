# Smart Signal System — OpenAPI Specification

This document provides a high-level overview of the cloud backend REST APIs. Since all services are built using **FastAPI**, fully interactive documentation (Swagger UI / ReDoc) is autogenerated and available at `/docs` or `/redoc` on each service port.

## Core Microservices

| Service | Port | Base Path | Description |
|---|---|---|---|
| **Vehicle Registry** | 8001 | `/api/v1/vehicles` | CRUD operations for managing the fleet of priority vehicles. |
| **Health Monitor** | 8002 | `/api/v1/nodes` | Heartbeat tracking, offline detection, and management of Edge Nodes at intersections. |
| **Event Service** | 8003 | `/api/v1/events` | Preemption event logging and WebSocket streaming. |
| **OTA Service** | 8004 | `/api/v1/ota` | Over-the-Air firmware rollout management for Edge Nodes. |

---

## 1. Vehicle Registry (`:8001`)

Manage emergency and transit vehicles capable of requesting signal priority.

- **`POST /api/v1/vehicles`** - Register a new vehicle.
- **`GET /api/v1/vehicles`** - List all vehicles (supports filtering by `agency_name` and `vehicle_type`).
- **`GET /api/v1/vehicles/{vehicle_id}`** - Get specific vehicle details.
- **`PATCH /api/v1/vehicles/{vehicle_id}`** - Update vehicle attributes.
- **`DELETE /api/v1/vehicles/{vehicle_id}`** - De-register a vehicle.

---

## 2. Health Monitor (`:8002`)

Track the health and status of the physical intersection edge nodes.

- **`POST /api/v1/nodes`** - Register a new intersection node.
- **`GET /api/v1/nodes`** - List all nodes, including their current `is_online` status and metadata.
- **`GET /api/v1/nodes/{node_id}`** - Get details for a specific node.
- **`PATCH /api/v1/nodes/{node_id}/status`** - Manually force a node offline/online for maintenance.

*(Note: Live heartbeats are ingested via MQTT/Kafka, not REST)*

---

## 3. Event Service (`:8003`)

The analytical logging service that tracks when an intersection is preempted.

- **`POST /api/v1/events`** - Log a new preemption event (called internally by `route-engine`).
- **`GET /api/v1/events`** - Query historical preemption events (with pagination and filters).
- **`PATCH /api/v1/events/{event_id}/clear`** - Mark a preemption event as completed (vehicle passed).

### Live WebSocket Stream (`ws://<host>:8003/api/v1/stream`)
The Event Service exposes a WebSocket connection used by the Dashboard UI to stream real-time JSON frames:
- `{"type": "vehicle.update", "vehicle_id": "...", "data": {...}}`
- `{"type": "node.preempt", "node_id": "...", "data": {...}}`
- `{"type": "node.heartbeat", "node_id": "...", "data": {...}}`

---

## 4. OTA Service (`:8004`)

Manage fleet-wide automated firmware updates.

- **`POST /api/v1/ota/releases`** - Upload a new firmware manifest and configuration file.
- **`GET /api/v1/ota/releases`** - List available firmware releases.
- **`POST /api/v1/ota/rollouts`** - Trigger a rollout of a specific release to targeted nodes.
- **`GET /api/v1/ota/rollouts/{rollout_id}/status`** - Monitor the real-time installation progress across the fleet.
